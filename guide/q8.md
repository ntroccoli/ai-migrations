# Q8 guide: Is the code uniform enough for one prompt, and what context goes with it?

For question 8 of the [checklist](../checklist.md): read it before writing up a finding on that
question. It walks through what the cases show; the project's owner decides. Each point names its
evidence: a lesson ID (its strength, its cases and the cases against it are in
[lessons/evidence.md](../lessons/evidence.md); its page links the case sections) or a case link.
"(ours)" marks the maintainer's reading, evidence level `ours`; so does a lesson tagged `[ours]` there,
which is our inference from its cases.

## Lessons behind it

- [CTX-1](../lessons/context.md): the right context moved results more than prompt wording.
- [CTX-2](../lessons/context.md): runtime facts a person would look at, such as a test's rendered
  output.
- [CTX-3](../lessons/context.md): field and API mappings written out and checked by a person.
- [CTX-5](../lessons/context.md): one change per prompt.
- [CTX-9](../lessons/context.md): with a small context budget, context chosen by fixed rules.
- [CTX-10](../lessons/context.md): docs and agent guidance that favour the old code steer agents
  back to it.
- [CTX-11](../lessons/context.md): units small enough to read whole.
- [CTX-12](../lessons/context.md), [CTX-13](../lessons/context.md): notes on why old code exists;
  rules kept beside the code they govern.
- [TOL-2](../lessons/tooling.md), [TOL-7](../lessons/tooling.md), [TOL-9](../lessons/tooling.md): a
  rule-based codemod or template first, the model after.
- [AGF-8](../lessons/agent-failures.md): one poorly supported language fell back to people.
- [PLN-8](../lessons/planning.md), [PLN-12](../lessons/planning.md): segments that cannot be
  specified left out; archetypes each with its own prompt.

Cases, in our words: Spotify dropped a framework too varied for one prompt; mapping tables fixed
wrong field mappings. Airbnb's choice of related files mattered more than wording; Slack gave the
model a codemod's partial output and each test's rendered output. Google's model handled Dart
poorly, so people did it; Uber's recipes did a move its AI attempt failed. Bloomberg gave each
kind of target its own prompt; stale docs misled Asana's agents; Pokémon split files the agent
would not open.

## What it looks like in a project

- Several kinds of code in scope (pure logic, concurrency, OS layer, UI, data pipelines), each
  needing its own prompt and examples (PLN-12).
- Renamed fields or APIs with no written mapping, which a model maps by name and gets wrong
  ([Zalando](../cases/2025-02-20-zalando-ui-component-libraries.md#what-went-wrong), CTX-3).
- Files too long for the model to read whole ([Pokémon](../cases/2026-01-25-vjeux-pokemon-showdown-rust.md#what-went-wrong)).
- Docs or agent instructions that still recommend the old library ([Asana](../cases/2026-08-07-asana-enzyme-to-rtl.md#what-went-wrong)).
- Prompts tuned to the old engine or model, still in use after the switch: nothing fails, the
  output is only worse, so the search for terms of the old engine covers prompts and instruction
  files too (ours; seen in a change of engine in the maintainer's own project, not a published
  case; near CTX-10).

## Questions to ask of this project

- Into which groups does the code fall, by kind, framework, build system and style?
- For each group, what context would an agent get: source, neighbours' tests, examples, mappings,
  runtime facts?
- What can a rule-based codemod do first?
- How does the model do on the hardest files of each language in scope?
- Which docs, instructions or prompts still point at the old stack or were tuned to the old
  engine?

## Trade-offs

- A codemod first anchors the model and costs rules that grow on long-tail patterns (TOL-2,
  TOL-4).
- A prompt per group gives better results and more prompts to maintain (PLN-12).
- Deferring a varied group or doing it by hand keeps the pipeline simple and leaves part of the
  move undone (PLN-8).

## When not to apply it

- Lessons about what models handle well or badly age fast: see whether
  [lessons/index.md](../lessons/index.md) marks AGF-8 or TOL-2 "may be outdated", and pilot on the
  model you will use (AGF-8).
- A small, uniform scope needs no grouping; the context list still applies (ours).
