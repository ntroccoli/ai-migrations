# Q7 guide: What does the old stack do implicitly?

For question 7 of the [checklist](../checklist.md): read it before writing up a finding on that
question. It walks through what the cases show; the project's owner decides. Each point names its
evidence: a lesson ID (its strength, its cases and the cases against it are in
[lessons/evidence.md](../lessons/evidence.md); its page links the case sections) or a case link.
"(ours)" marks the maintainer's reading, evidence level `ours`; so does a lesson tagged `[ours]` there,
which is our inference from its cases.

## Lessons behind it

- [REV-3](../lessons/review.md): a written list of constructs that read alike in old and new code
  but behave differently, given to reviewers.
- [OPS-4](../lessons/operations.md): what the old runtime supplied silently, tested on every
  platform shipped.
- [TST-7](../lessons/testing.md): values beyond the old range, at real data sizes, where numeric
  types or sums change.
- [VER-6](../lessons/verification.md): machine-readable contracts so a changed interface fails
  mechanically.
- [SEC-5](../lessons/security.md), [SEC-6](../lessons/security.md): binding signatures generated by
  a tool; a bounds-checked target turns silent errors into crashes.
- [AGF-3](../lessons/agent-failures.md): agents handled order-dependent steps badly even when told.
- [SEC-10](../lessons/security.md): the order of schema changes and backfills kept with people.

Cases, in our words: the regressions compiled: GitHub's runtime defaults and one-sided paired
operations, Bun's lines that read alike but behave differently, Intel's pointer comparison,
Google's bit operations and SQL tied to the old width, 1Password's backfill order, Zalando's wrong
data mapping that broke a live page, PagerDuty's equality change.

## What it looks like in a project

- Code that relies on defaults: a time zone, an environment read, a falsy check, a number type
  ([GitHub](../cases/2026-09-16-github-copilot-runtime-rust.md#what-went-wrong)).
- Paired operations (open and close, subscribe and unsubscribe) where a port may carry one side
  only ([GitHub](../cases/2026-09-16-github-copilot-runtime-rust.md#what-went-wrong)).
- Each item of the [pitfalls](../pitfalls.md) list for this kind of move, found in the scope by a
  search you can name (ours).
- A direct dependency whose target replacement is unmaintained or behaves differently (SEC-7).

## Questions to ask of this project

- Which items of the pitfalls list for this move appear in the scope, and by which search?
- Which direct dependencies have a stable equivalent in the target, and which are archived?
- Which orders (schema, writers, backfill) must hold across the switch, and who sets them?

## Trade-offs

- A written list of look-alike constructs helps reviewers and agents, and takes a person who knows
  both stacks to write (REV-3).
- Testing every shipped platform catches runtime defaults and multiplies the test matrix (OPS-4).

## When not to apply it

- A pitfalls item marked "(ours)" has no case behind it: search for it, and weigh what you find as
  the maintainer's inference (ours).
- A move within one runtime (a library upgrade) keeps most runtime defaults; the release notes
  between the two versions are the better list there (ours).
